Error Handling

This document describes error handling patterns and error responses in the Riello UPS Servers Shutdown system.

HTTP API Errors

Error Response Format

All API errors return a JSON object with consistent structure:

{
  "success": false,
  "error": "Description of the error"
}

HTTP Status Codes

Status CodeMeaningWhen Returned
200OKRequest succeeded (even if operation failed)
404Not FoundUnknown endpoint
500Internal Server ErrorUnhandled exception
Note: The dashboard returns HTTP 200 even for failed operations, with the error details in the JSON body. Check the success field to determine actual operation status.

Common API Errors

Client Not Found

{
  "success": false,
  "error": "Client not found"
}

Cause: Attempting to update shutdown delay for non-existent hostname.

Resolution: Verify the hostname exists in the clients list.

Invalid Parameter

{
  "success": false,
  "error": "Invalid seconds value"
}

Cause: Non-numeric or negative value for shutdown delay.

Resolution: Provide a positive integer for seconds parameter.

Database Error

{
  "success": false,
  "error": "Database error: ..."
}

Cause: SQLite database access failure.

Resolution: Check file permissions on ups_clients.db.

Client Error Handling

# Client reconnection logic with exponential backoff
def run(self):
    retry_delay = 10  # Start with 10 seconds
    max_retry_delay = 60  # Cap at 60 seconds
    
    while self.running:
        try:
            self.discover_server()
            self.connect()
            self.run_connected()
            retry_delay = 10  # Reset on successful connection
        except socket.error as e:
            logging.error(f"Connection error: {e}")
            time.sleep(retry_delay)
            retry_delay = min(retry_delay * 2, max_retry_delay)
        except Exception as e:
            logging.error(f"Unexpected error: {e}")
            time.sleep(retry_delay)

Server Error Handling

# Server handles client disconnection gracefully
def handle_client(self, client_socket, address):
    try:
        while self.running:
            data = client_socket.recv(4096)
            if not data:
                break  # Client disconnected
            self.process_message(data, address)
    except socket.error as e:
        logging.warning(f"Client socket error: {e}")
    finally:
        self.remove_client_by_socket(client_socket)
        client_socket.close()

UPS API Error Handling

def get_minutes(self) -> int:
    """Fetch battery autonomy from UPS API.
    
    Returns:
        int: Battery minutes remaining, or None on error
    """
    ctx = ssl.create_default_context()
    ctx.check_hostname = False
    ctx.verify_mode = ssl.CERT_NONE
    
    try:
        req = urllib.request.Request(self.url)
        with urllib.request.urlopen(req, timeout=10, context=ctx) as response:
            data = json.loads(response.read().decode())
            return data.get('autonomy')  # Returns None if key missing
    except urllib.error.URLError as e:
        logging.error(f"UPS URL error: {e}")
        return None
    except socket.timeout:
        logging.error("UPS API timeout")
        return None
    except json.JSONDecodeError as e:
        logging.error(f"UPS JSON parse error: {e}")
        return None
    except Exception as e:
        logging.error(f"Unexpected UPS error: {e}")
        return None

Recovery Strategies

Automatic Recovery

Failure TypeRecovery Strategy
Client disconnectAutomatic reconnection with backoff
Server restartClients rediscover and reconnect
UPS API failureContinues polling, logs error
Database errorRetries on next operation

Manual Recovery

IssueResolution
Service won't startCheck logs, verify permissions, check ports
Database corruptionDelete ups_clients.db, restart services
Stuck shutdown flagRestart UPSserver service
Client not appearingCheck firewall, verify UDP broadcast
