Getting Started Guide

This guide walks you through setting up the Riello UPS Servers Shutdown system from scratch.

Prerequisites

Hardware Requirements

  • Riello UPS with network connectivity and JSON API support
  • Linux server to run UPS server components (the machine that shuts down last)
  • One or more client machines (Linux, macOS, or Windows)

Software Requirements

  • Python 3.6 or higher on all machines
  • systemd (for service management on Linux)
  • Network connectivity between all machines

Network Requirements

PortProtocolDirectionPurpose
5225UDPBroadcastServer discovery
5226TCPInbound to serverClient connections
8080TCPInbound to serverDashboard web interface

Step 1: Verify UPS API

First, verify your Riello UPS JSON API is accessible:

# Test UPS API (replace with your UPS IP)
curl -k https://192.168.1.1/json/live_data.json

# Expected response includes:
# { "autonomy": 120, ... }

Note the URL - you'll need it for configuration.

Step 2: Install Server Components

On the server machine (the one that should shut down last):

# Clone or download the repository
git clone https://github.com/your-repo/UPS-Riello-Servers-Shutdown.git
cd UPS-Riello-Servers-Shutdown

# Create installation directory
sudo mkdir -p /opt/UPSserver

# Copy server files
sudo cp server/UPSserver.py /opt/UPSserver/
sudo cp server/UPSdashboard.py /opt/UPSserver/

# Install systemd service files
sudo cp server/UPSserver.service /etc/systemd/system/
sudo cp server/UPSdashboard.service /etc/systemd/system/

# Install logrotate configurations
sudo cp server/UPSserver.logrotate /etc/logrotate.d/UPSserver
sudo cp server/UPSdashboard.logrotate /etc/logrotate.d/UPSdashboard

# Reload systemd
sudo systemctl daemon-reload

# Enable services to start on boot
sudo systemctl enable UPSserver UPSdashboard

# Start services
sudo systemctl start UPSserver UPSdashboard

# Verify services are running
sudo systemctl status UPSserver UPSdashboard

Step 3: Configure Server

Open the dashboard in your browser:

http://<server-ip>:8080

Configure the following settings:

  1. UPS URL: Enter the full URL to your UPS JSON API
    https://192.168.1.1/json/live_data.json
  2. Minimum Minutes: Set the battery threshold (e.g., 15 minutes)
    Shutdown triggers when battery drops to or below this value

Step 4: Install Client Components

On each client machine that should be shut down during power outages:

Linux/macOS

# Create installation directory
sudo mkdir -p /opt/UPSclient

# Copy client file
sudo cp client/UPSclient.py /opt/UPSclient/

# Install systemd service (Linux only)
sudo cp client/UPSclient.service /etc/systemd/system/

# Install logrotate configuration
sudo cp client/UPSclient.logrotate /etc/logrotate.d/UPSclient

# Reload systemd and start
sudo systemctl daemon-reload
sudo systemctl enable UPSclient
sudo systemctl start UPSclient

# Verify client is running
sudo systemctl status UPSclient

Windows

Run the client manually or set up as a Windows service:

# Run client (requires Administrator)
python C:\UPSclient\UPSclient.py

Step 5: Configure Shutdown Delays

Once clients connect, they appear in the dashboard. Configure shutdown delays:

  1. Open dashboard: http://<server-ip>:8080
  2. Find each client in the list
  3. Set shutdown delay in seconds:
    • 0: Shut down immediately when triggered
    • 30: Wait 30 seconds before shutdown
    • 60: Wait 60 seconds before shutdown
  4. Click "Update" to save
Tip: Set delays based on service dependencies. For example:
  • Web servers: 0 seconds (shut down first)
  • Application servers: 30 seconds
  • Database servers: 60 seconds
  • UPS server machine: Always shuts down last automatically

Step 6: Verify Setup

Check Server Logs

# View server logs
sudo tail -f /var/log/UPSserver.log

# Expected output:
# 2024-01-15 10:00:00 - INFO - UPS Server started on port 5226
# 2024-01-15 10:00:05 - INFO - Client web-server-01 connected from 192.168.1.100

Check Client Logs

# View client logs
sudo tail -f /var/log/UPSclient.log

# Expected output:
# 2024-01-15 10:00:05 - INFO - Discovered server at 192.168.1.10
# 2024-01-15 10:00:05 - INFO - Connected to server

Verify Dashboard

  1. Open http://<server-ip>:8080
  2. Verify all clients appear in the list
  3. Verify UPS battery minutes are displayed
  4. Verify configuration shows correct values

Firewall Configuration

If you have a firewall enabled, open the required ports:

Server Firewall (iptables)

# Allow UDP discovery
sudo iptables -A INPUT -p udp --dport 5225 -j ACCEPT

# Allow TCP client connections
sudo iptables -A INPUT -p tcp --dport 5226 -j ACCEPT

# Allow dashboard access
sudo iptables -A INPUT -p tcp --dport 8080 -j ACCEPT

# Save rules (Debian/Ubuntu)
sudo netfilter-persistent save

Server Firewall (firewalld)

# Allow ports
sudo firewall-cmd --permanent --add-port=5225/udp
sudo firewall-cmd --permanent --add-port=5226/tcp
sudo firewall-cmd --permanent --add-port=8080/tcp

# Reload firewall
sudo firewall-cmd --reload

Testing

Test Client Discovery

# On a client machine, check if it can discover the server
# The client log should show:
# "Discovered server at 192.168.1.10"

Test UPS Monitoring

# Check server log for UPS readings
grep "UPS battery" /var/log/UPSserver.log

# Should show periodic readings:
# "UPS battery: 120 minutes remaining"

Test Shutdown (Optional)

Warning: This will actually shut down the test machine!

To test without actual shutdown, you can temporarily modify the client to log instead of shutdown:

# In UPSclient.py, temporarily change:
# subprocess.run(['shutdown', '-h', 'now'], check=True)
# To:
# logging.info("WOULD SHUTDOWN NOW")

Troubleshooting

Client Not Connecting

  1. Check UDP broadcast is working (port 5225)
  2. Verify server is running: systemctl status UPSserver
  3. Check firewall rules
  4. Verify network connectivity between client and server

Dashboard Not Accessible

  1. Verify dashboard service: systemctl status UPSdashboard
  2. Check if port 8080 is in use: ss -tlnp | grep 8080
  3. Check firewall allows port 8080

UPS Status Shows "Unknown"

  1. Verify UPS URL is correct in dashboard configuration
  2. Test UPS API manually: curl -k <UPS_URL>
  3. Check server error log: tail /var/log/UPSserver_error.log
